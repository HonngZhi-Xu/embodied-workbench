## 二、定位与开发方式

一个统一工作台覆盖设备接入、遥操作示教、数据治理、模型训练、模型资产与受控执行。近期用 UR5e + GELLO + 二指夹爪 + RealSense + PaXini M3025 验证抓取放置；G1 + 因时灵巧手及 SONIC/TeleopIt/SuperMimic 作为后续适配。

建议首期采用模块化单体：一个 Web UI、一个本地 Python 服务、一个独立训练子进程和一个资产数据库。图中的 E/C/S 编号为模块边界，不要求各自拆成微服务。多人、多设备时再拆分训练节点、对象存储、身份与同步服务。

DP/ACT/VLA 属于操作策略能力；SONIC/SuperMimic 属于全身控制框架的适配对象。它们需要独立输入输出、运行时与设备契约，不能作为可任意互换的单一模型下拉框。

## 四、统一数据与模型存储

数据库保存结构化索引，实际文件保存在本地/共享文件系统/对象存储。数据库通过 asset_id、URI、文件大小与 SHA256 关联文件，不将大量 RGB 帧和模型权重直接塞入业务表。

```text
edge_data/
  registry.db                  # 规划：统一资产数据库
  captures/<episode_id>/       # 原始数据与来源/标定/时戳
  datasets/<id>/<version>/     # 规划：版本成员、处理配置和划分清单
  runs/<run_id>/               # 实验配置、环境、日志、检查点
  models/<id>/<version>/       # 规划：注册模型包及评测/兼容契约
  backups/                     # 规划：备份策略与恢复记录
```

当前实际代码保存到 captures/*.zarr、merged-*.zarr、runs/*；上述目录为目标组织方式，需通过迁移/登记适配，不能直接更改已记录的文件位置而不更新索引。

### 主要业务实体

| 实体 | 重要关系与约束 |
| --- | --- |
| projects / tasks | 任务属于项目，固定任务说明、标签定义和验收方法 |
| devices / device_profile_versions | 设备及其不可变配置版本，包含关节、传感器角色、标定与单位 |
| episodes | 关联任务、设备配置版本、数据资产、采集来源、质量和成功标记 |
| datasets / dataset_versions | 逻辑数据集及不可变版本，唯一约束 (dataset_id, version) |
| dataset_members | 固定片段、选取范围与 train/validation/test 分区；不跨片段随机拆相邻帧 |
| training_runs | 关联数据集版本、代码提交、环境、超参数、随机种子与运行状态 |
| models / model_versions | 模型族及注册版本，关联训练实验、文件资产、归一化、输入输出与设备契约 |
| evaluations | 关联模型版本和任务，记录场景、试验次数、成功、掉落、超时与接管 |
| deployments / runtime_events | 关联模型与目标节点，记录激活/撤回/回退及运行结果、失败回流 |
| file_assets | URI、校验值、大小、格式、存储后端、备份与完整性状态 |
| users / roles / audit_logs | 用户、项目访问与资源操作审计；不把大文件正文放进审计记录 |

原始采集片段原则上保留，修复和预处理生成新资产并记录来源；冻结版本不可原地替换。错误样例可登记为 invalid，不应为通过训练而静默删行。清理时先做引用检查，避免删除模型依赖的数据资产；删除/归档操作需有权限与审计。

## 五、模型包与发布契约

```text
model_version/
  checkpoint.ckpt
  config.yaml
  dataset_manifest.json
  environment.json
  device_profile.json
  input_output_contract.json
  evaluation.json
  checksums.json
```

归一化可以保存在检查点中，但注册流程必须验证其存在和对应的观测/动作维度。模型输入须固定相机角色、图像预处理、触觉单位与维度、关节顺序、时序窗口；模型输出须固定关节/TCP/全身参考的语义、单位、坐标系和更新节奏。

PaXini 原始分布触觉和合力分别记录单位，不把未核验的 counts 当作 N。模型版本不得因为文件名相同就覆盖已发布内容。候选模型经过评测和兼容检查后才进入可部署状态。

## 六、部署边界

- 端：UR/G1 控制器、执行器、传感器和已有现场控制路径。
- 边：设备连接、遥操作数采、多模态记录、本地缓存、后续受控策略执行。实时指令和异常处置不依赖云端往返。
- 云/私有服务器：资产数据库、训练和模型管理；首期可同机，后续部署到实验室 GPU 服务器。
- 在线 Site：目前提供演示、文档/安装包入口；本地实机页面由边缘服务同源提供。目前不存在在线 Site 自动控制内网机器人或自动同步所有数据的能力。

当前训练由本地子进程执行，平台没有真实的机器人运动部署接口。图中的模型下发与受控执行属于后续研发范围。

## 七、研发分期与可检查成果

1. **现场验证与契约固定**：确认 UR5e/夹爪/相机/M3025 配置，验证串口、帧合法性、采集间隔和真实数据质量。成果：设备档案与一批可回放、可训练示教。
2. **资产数据库与数据版本**：创建业务表、迁移与登记工具，记录原始片段和冻结数据集版本，明确备份。成果：服务重启后可找回数据与版本，导入幂等，文件引用可验证。
3. **实验与模型注册**：训练任务入库、恢复运行状态、生成模型包、记录离线/实机评测。成果：从模型可追溯到数据、代码、环境和超参数。
4. **受控执行闭环**：推理、动作适配、控制权、异常处理、版本发布/回退与失败回流。成果：在现场独立评测任务中验证操作成功与接管机制。
5. **人形及端边云扩展**：G1/因时、SONIC/TeleopIt/SuperMimic、VLA、多节点训练/数据同步。成果：在同一资产和任务接口下增加设备与算法适配器。
